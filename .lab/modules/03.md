## Module 3 — Fix the broken producer

**Goal:** debug a failure that raises no error, and understand why measurement
time and arrival time are different facts.

A colleague has written a variant producer,
[`producer/produce_v2.py`](producer/produce_v2.py). It runs. It reports success.
Every sample it sends arrives. Every value is correct.

The traces it produces are jumpy.

### See it for yourself

```bash
docker compose up -d --wait kafka stream-api key-generator
cd producer && python produce_v2.py --laps 1
cd ../consumer && npm start
```

The consumer now reports on timestamp continuity, and it will tell you what it
found:

```
  Timestamps: 118 DISCONTINUITIES across 11 channels.
  Worst single gap: 14.203 ms on Speed:SandbourneGT3
  Total drift:      1284.6 ms

  Each gap is a hole in the recorded timeline. The samples are all
  present, but they claim to have happened at the wrong moments.
```

### Your task

Find out why, and fix `produce_v2.py`.

Nothing crashed. Nothing was dropped. The bug is entirely in *when the data
claims to have happened*.

<details>
<summary>A nudge, if you want one</summary>

A `PeriodicDataPacket` does not carry a timestamp per sample. It carries a
**start time** and an **interval**, and the consumer reconstructs the rest. That
is a large saving for evenly spaced data — and it means the producer is making a
promise about where each batch sits on the timeline.

So: after a batch is written, where does the start time for the *next* batch
come from? Look at that line in `produce_v2.py`, and compare it against the same
line in `produce.py`, which is correct.

</details>

### Why this matters more than it looks

Telemetry is worth keeping because you can go back to it. A recording where the
values are right but the moments are wrong is worse than no recording: it looks
completely fine, it plots without complaint, and every conclusion drawn from it
about *when* something happened is wrong.

Arrival time is a real and useful thing to measure — it tells you about latency.
It is simply not the same fact as measurement time, and a producer that
substitutes one for the other silently destroys the difference.
